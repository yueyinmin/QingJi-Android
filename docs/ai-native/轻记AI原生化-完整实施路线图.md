> 基线 HEAD：`c97ada3d98678cc7f178061a84404b64a95d6066`

## 0. 阶段编号口径

本文件是六份文档中**唯一阶段编号来源**。所有文档均以本表为准：

| 阶段 | 名称 | 核心职责 |
|---|---|---|
| A | 完整代码审计 | 明确现有代码、能力和缺口 |
| B | AI 基础设施 | Provider、SSE、Tool Calling、模型能力 |
| C | Agent 与工具调用 | ContextBuilder、Agent、只读工具 |
| D | AI 对话页面 | 统一 AI 管家和业务上下文入口 |
| E | 提案与权限系统 | ProposalManager、确认、版本控制、幂等执行 |
| F | AI 饮食助手 | 食物识别、匹配、本地营养计算 |
| G | AI 训练助手 | 训练分析、训练反馈、计划优化 |
| H | 身体数据与综合分析 | 身体趋势、减脂分析、综合报告 |
| I | AI 长期记忆 | 用户偏好、训练记忆、饮食记忆 |
| J | 主动 AI 管家 | 事件触发、主动建议 |
| K | 数据安全与隐私 | 数据最小化、密钥、日志、隐私控制 |
| L | 性能与稳定性 | 性能优化、备份恢复、异常恢复 |
| M | 全量测试与最终验收 | 全链路测试和正式交付 |

阶段编号是项目管理编号，不代表基础安全能力必须等到 K 阶段。B 阶段必须具备基本密钥安全、日志脱敏、请求取消和上下文最小化；K/L 负责完善与专项验收。

## 1. 依赖关系总览

```text
A 审计
 ├─ B AI 基础设施 ── C Agent/工具 ── D 会话页
 │                         │
 │                         └── E 提案/版本/幂等 ─┬─ F 饮食助手
 │                                               ├─ G 训练助手
 │                                               └─ H 身体分析
 ├── K 数据安全与隐私（B 起有基础实现，K 做完整专项）
 ├── L 性能与稳定性（含备份恢复/异常恢复，B 起有降级基线）
 └── I 记忆（D 后） ── J 主动 AI（I 后） ── M 全量验收
```

关键门禁：

- 没有 B，不可能有真正的 C（Agent 需要 SSE/Tool Calling）。
- 没有 E，不允许任何 AI 写入正式业务数据。
- F 依赖 E 的提案确认卡片，但 F 的匹配引擎可提前做只读设计。
- G 依赖 E 的版本控制；训练计划无 version 是硬阻塞。
- J 必须在 I 与本地规则去重机制之后。
- K/L 贯穿，但正式验收放在 M。

## 3. 阶段 B：AI 基础设施

| 项 | 内容 |
|---|---|
| 目标 | 可测试、可替换、可取消的 AI 服务层 |
| 前置 | A 完成 |
| 主要工作 | `AiProvider` 抽象；能力声明；OpenAI 兼容适配器；SSE；Tool Calling；流式工具参数；JSON Schema；统一错误模型；配置管理；请求取消；MockWebServer；**API Key 安全复用、日志脱敏、上下文最小化、网络失败降级（R7 前置基线）** |
| 范围收口 | **阶段 B 仅保留 IMAGE_INPUT 能力声明与现有图片接口兼容；中餐识别/匹配/营养计算属于 F；语音不作为 B 阻塞项（R5）** |
| 复用 | `AiClient` 的错误分类、图片输入、`json_object` 降级、超时与日熔断；`ApiKeyStore` |
| 新增能力 | 流式事件模型、能力探测、client 注入、取消、strict schema 降级策略 |
| 风险 | 供应商协议差异；`response_format` 静默降级；无网络层测试 |
| 验收 | 见《阶段验收标准》B 节 |
| 禁止 | 不改业务 Repository；不做 Agent；不做会话页 |

## 4. 阶段 C：Agent 与只读工具

| 项 | 内容 |
|---|---|
| 目标 | AI 能调用本地真实业务数据 |
| 前置 | B 验收通过 |
| 主要工作 | `QingJiAgent`、`ContextBuilder`、`ToolRegistry`、`ToolExecutor`；4 个只读工具；循环/超时/重复防护；**多 tool_call 按 callId 回传、流式参数完整拼接后执行、结构化工具错误、只读白名单不可覆盖（R8）** |
| 职责边界 | **阶段 C 只读，不含 ProposalManager；提案在 E（R1）** |
| 复用 | `QingJiRepository`、`TrainingRepository`、`HealthRepository`、`NutritionCalculator`、`SessionCalorieCalculator`、`ExerciseCalculator` |
| 新增能力 | Tool Schema、只读白名单、Flow→suspend 快照、JSON DTO |
| 限制 | 单任务 ≤4 轮模型交互；单轮 ≤5 工具；单任务 ≤10 工具；单工具默认 10s |
| 风险 | Repository 带副作用；AI 不得直连 DAO；上下文数据泄露 |
| 验收 | 工具结果与业务页面一致；无写库 |
| 禁止 | 任何写入工具；会话 UI |

## 6. 阶段 E：提案系统与安全执行

| 项 | 内容 |
|---|---|
| 目标 | 所有正式写入可控、可追踪、可回滚状态 |
| 前置 | D 具备提案卡片展示位；**R2/R3/R4/R6 DB 决策已定稿（R12）**；主库执行记录为唯一权威 |
| 主要工作 | `ProposalManager`；提案确认页；版本字段/CAS；幂等键；执行日志；跨库一致性；STALE 处理 |
| 复用 | 现有事务入口、备份标志模式、`exercise_session_calorie` 业务键模式 |
| 新增能力 | 提案状态机、乐观锁、幂等执行、对账 |
| 阻塞 | 训练计划无 version；营养目标无版本；AI 库未建 |
| 风险 | 跨库状态不一致；恢复后旧提案误执行 |
| 验收 | 重复确认、版本冲突、崩溃恢复、过期提案全部通过 |
| 禁止 | 未通过前上线任何 AI 写工具 |

## 7. 阶段 F：AI 饮食助手

| 项 | 内容 |
|---|---|
| 目标 | 图片/文本 → 本地匹配 → 本地计算 → 用户确认 → 正式记录 |
| 前置 | E 验收；食物匹配数据方案决策 |
| 主要工作 | AI 结构化识别；`FoodMatchingEngine`；通用别名作为**版本化只读食物数据**（不放 AI 库，R6）；用户纠正存主库用户侧表；混合召回；精排；`NutritionCalculator`；饮食确认卡片 |
| 复用 | `ImageRecorder`、`AiClient.recognizeImage`、`NutritionMatch`、`NutritionCalculator`、`QingJiRepository.addFoodLog`（经提案） |
| 新增能力 | 别名/规则排序/无匹配/估算标记/确认卡片 |
| 风险 | 中餐菜名覆盖不足；模型输出营养数值不可信；确认前误写库 |
| 验收 | 别名、组合菜、无匹配、重量修改、营养重算、正式写入均通过 |
| 禁止 | 模型直接决定营养值；强行匹配相似食物 |

## 10. 阶段 I：AI 长期记忆与用户画像

| 项 | 内容 |
|---|---|
| 目标 | 可管理的用户记忆，避免每次从零开始 |
| 前置 | D 会话系统 |
| 主要工作 | 记忆分类、来源追踪、过期/失效、用户查看与纠正、按任务检索；**区分用户事实与 AI 推断；删除会话不等于删除长期记忆，删除记忆需用户显式操作（R10）** |
| 复用 | 现有偏好/目标/常吃食物数据 |

| 验收 | 记忆有来源、可修改、可失效、不污染公共食物库 |
| 禁止 | 不把聊天记录全量作为长期记忆 |

## 11. 阶段 J：主动 AI 管家

## 15. 首批实施工单建议

严格按阶段单独生成工单，建议顺序：

1. `QJ-AI-B01`：Provider 抽象 + OpenAI 兼容一次性请求迁移 + 能力探测 + MockWebServer。
2. `QJ-AI-B02`：SSE + 流式事件模型 + 取消。
3. `QJ-AI-B03`：Tool Calling + 流式参数拼接 + JSON Schema 降级。
4. `QJ-AI-C01`：ToolRegistry / ToolExecutor / 4 只读工具。
5. `QJ-AI-C02`：QingJiAgent 循环与 ContextBuilder。
6. `QJ-AI-D01`：AI 管家页与上下文入口。
7. `QJ-AI-E01`：版本字段/CAS + 提案状态机 + 幂等。
8. 后续 F/G/H/I/J/K/L/M 按依赖生成。

## 16. 范围纪律

- 不因 AI 改造重构训练、饮食、统计业务。
- 不为“架构整齐”新增无证据的 Repository/表。
- 不把编译通过等同于阶段验收。
- 发现额外问题先记录，不扩大当前阶段范围。
