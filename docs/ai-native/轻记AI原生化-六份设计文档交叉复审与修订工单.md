## 2. 必须修正项与最终决议

| 编号 | 问题 | 最终决议 | 落点 |
|---|---|---|---|
| R1 | 阶段编号与职责偏差 | 全部文档以《完整实施路线图》阶段表为唯一来源；阶段 C 为只读 Agent，**不得出现 ProposalManager 实施职责**；ProposalManager 仅在阶段 E 正式实施；F/G 写入依赖 E 验收 | 架构设计、路线图、审计报告、验收标准 |
| R2 | 提案执行状态权威来源不清 | **主库 `ai_proposal_execution` 是业务执行唯一权威依据**；AI 库只存提案展示状态；启动/恢复时按 `idempotency_key` 对账；AI 库状态不得决定 EXECUTED/FAILED | 数据库设计、架构设计、验收标准 |
| R3 | 事务失败时写 FAILED 会随回滚丢失 | 执行前完成参数/权限/版本校验；主库事务只写正式数据 + 成功执行标记；事务失败整体回滚，失败记录与原因在事务外单独写；`EXECUTING` 启动扫描超时后转 FAILED 或重新入队 | 数据库设计、验收标准 |
| R4 | 训练计划/营养目标版本控制未定稿 | **训练计划父表 `version: Long + updatedAt` 为唯一版本源**，计划日/动作明细随父版本整体替换，不单独建版本；所有人工/AI/模板/备份恢复写入统一维护版本；营养目标暂留在 `UserProfile`，新增 `goalVersion + goalUpdatedAt`，不新建目标表 | 数据库设计、复用清单、验收标准 |
| R5 | 阶段 B 图片能力范围偏大 | 阶段 B 仅保留 `IMAGE_INPUT` 能力声明与现有图片接口兼容；中餐识别、别名匹配、营养计算全部在阶段 F；语音不作为阶段 B 阻塞项 | 路线图、验收标准 |
| R6 | 食物别名归属未定 | 通用别名作为**版本化只读食物数据**维护，随食物库资源版本发布；用户个人纠正存主库用户侧表；AI 库不放公共词库；模型不得修改别名数据 | 数据库设计、复用清单、路线图 |
| R7 | 隐私与性能后置 | 从阶段 B 起强制：API Key 安全复用、日志脱敏、上下文最小化、请求取消、网络失败降级；K/L 只做完整专项验收 | 路线图、验收标准、架构设计 |
| R8 | Tool Calling 协议细节不足 | 单响应可含多个 tool_call；允许并行执行但必须按 callId 回传；流式参数必须完整拼接后执行；失败返回结构化工具错误；工具响应按供应商协议回传；只读白名单不可被模型覆盖 | 架构设计、验收标准 |
| R9 | 数据来源与结论可信度未标识 | 所有分析结果区分：实际记录 / 本地计算 / AI 推断 / 数据不足 / 建议；ContextBuilder 与消息类型均带来源标识 | 架构设计、验收标准 |
| R10 | 长期记忆治理不足 | 记忆可查看/纠正/失效/过期；区分用户事实与 AI 推断；按任务检索相关记忆；删除会话不等于删除长期记忆，删除记忆需用户显式操作 | 架构设计、路线图、验收标准 |
| R11 | 基线测试报告与 HEAD 不一致 | 重跑 `compileDebugKotlin` + `testDebugUnitTest`；以重跑结果为阶段 B 回归基准，旧 XML 不作为权威 | 审计报告、本工单 |
