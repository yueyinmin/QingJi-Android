## 五、阅读顺序建议

1. 先看 `完整实施路线图` 确定阶段与依赖。
2. 再看 `完整代码审计报告` 与 `现有功能复用清单` 确认真实代码基础。
3. 进入具体阶段前，阅读对应专项定稿文档：
   - B/C：ToolCalling协议、Git基线
   - E：提案状态机、版本控制
   - F：食物匹配与别名
   - I：长期记忆边界
4. 验收时以 `阶段验收标准` 为准。

## 六、已定稿的关键规则

- B 阶段只读基础设施；C 阶段只读 Agent；E 阶段才实施 ProposalManager 与写入。
- 主库执行记录是业务执行唯一权威；AI 库只展示并对账。
- 训练计划父表 version 为唯一版本源；营养目标在 UserProfile 内加目标版本。
- 通用食物别名是版本化只读食物数据；用户纠正存用户侧。
- AI 输出区分 FACT / CALCULATED / INFERRED / UNKNOWN / SUGGESTION。
- B 阶段起必须满足基础安全、日志脱敏、上下文最小化、请求取消和网络降级。
