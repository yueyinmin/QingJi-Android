## 三、P0 实现要点

### 3.1 并发互斥（工单三）
- `save()` 入口 `savingGuard.compareAndSet(false, true)`：调用线程立即上锁，协程调度前第二次点击即被拒；不依赖 UI 禁用。
- `_isSaving: StateFlow<Boolean>` 供 UI 反馈。
- `finally` 无条件释放锁与标志，覆盖成功、校验失败、异常三条路径。
- 测试 T12：`saveHook` 用 `CompletableDeferred` 卡住第一次保存，连续两次 `save()`，验证第二次返回 false、`entered==1`、只有 1 场训练 / 1 份明细 / 1 条账本。

### 3.2 草稿快照一致性（工单四）
- 入口取 `_draft.value` 不可变快照 `snapshot`，整段 DB 操作只读它。
- `persist()` 递增 `revision` 并落盘；成功时仅当 `_draft.value.revision == snapshotRevision` 才清草稿；否则保留新草稿并提示。
- 数据库异常（`saveHook` 抛错）时草稿一字不动，`onDone(false)`，`finally` 释放锁；重试成功。
- 测试 T14/T11 分别验证上述两点。
- 进程恢复测试：写入真实 `SharedPreferences`，丢弃 Store 后新建 `WorkoutDraftStore` 读同一磁盘文件，验证力量组、有氧类型、目标 JSON、实际时长/距离、revision、来源全部恢复（非重建 ViewModel 代替）。
