## 四、关键修复说明

### 4.1 异常分层（P0-1 / P0-2）

`save()` 的协程体拆成两段 try：

- 第一段（数据库段）：只含 `repo.saveUnifiedSession()`。`catch (CancellationException) → throw`（重抛）；其他 `Exception → onDone(false)` + 保留草稿后 `return@launch`。
- 第二段（成功后段）：草稿版本化清理、提示、UI 回调。异常只提示"界面刷新遇到问题"，**绝不改数据库结果**；`onDone(true)` 用 `runCatching` 包裹，其异常不外溢、不二次调用 `onDone(false)`。
- `finally`：所有正常/异常/取消路径释放 `savingGuard` 与 `_isSaving`。

### 4.2 sessionUuid 语义（P0-3，T15/T16 证明）

- 新建训练：`sessionUuid = random UUID`，`editingUuid = ""`。保存期间修改草稿后保留的新草稿沿用同一 `sessionUuid`。
- 编辑历史：`editSession()` 中 `sessionUuid = editingUuid = 历史场 uuid`。
- 两次保存都 `sessionDao.insert(session)`（同 uuid REPLACE），因此：
  - 新建场景第二次保存 → 更新同一场，不产生重复会话；
  - 编辑场景第二次保存 → 仍更新原历史场，不改日期/来源、不波及其他历史场。
- 上述均由真实 Room + Repository 两次保存测试证明（T15/T16）。

### 4.3 revision 落盘一致性（P1-1，T20 证明）

`persist()` 改为：先 `draftStore.save(versioned)` → 成功后再 `_draft.value = versioned`；落盘抛异常时内存保持旧值并提示，保证内存与磁盘 revision 始终一致。

### 4.4 备份事务回滚（P1-2）

用真实 `parseBackup()` 构造合法 v8 备份，`db.withTransaction { restoreInto() }` 内在训练段清表后抛异常，验证已有 session / 力量明细 / 有氧明细 / 账本 / 日记投影全部回滚保留。**这不同于 B1.1.1 的 JSON 解析失败测试。**
