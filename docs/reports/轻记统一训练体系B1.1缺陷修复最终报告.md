## 3. 各类型真实保存路径

| 类型 | 保存表 | 实际字段 | 目标字段 |
|---|---|---|---|
| STRENGTH | `workout_exercise` | `setsJson`（reps/weight/durationSec） | `WorkoutSet.targetReps/targetWeightKg` + `itemMetaJson.tc` |
| CARDIO | `workout_cardio_detail` | `durationSeconds`、`distanceMeters`、`rawInputJson`（WorkoutItem JSON） | `rawInputJson.tc`（TargetConfigJson） |
| HIIT | `workout_exercise` | `itemMetaJson.ws/rs/rn/d` | `itemMetaJson.tc` |
| FLEXIBILITY | `workout_exercise` | `itemMetaJson.d/c` | `itemMetaJson.tc` |
| OTHER | `workout_exercise` | `itemMetaJson.d/rp` | `itemMetaJson.tc` |

`WorkoutExercise.itemMetaJson`、`WorkoutCardioDetail.rawInputJson` 均为版本化 `WorkoutItem` JSON（schemaVersion=1），解析失败降级为旧数据语义，不丢其他字段。

## 4. 数据库与备份版本

- **Room 版本保持 v22，未新增 migration，未清库，未改写历史数据。** 所需列（recordType / targetConfigJson / itemMetaJson / workout_cardio_detail）已在 v22 中存在。

## 8. 暂缓能力与已知限制

1. **HIIT/FLEXIBILITY/OTHER 完整能力**：本次只保证类型、目标配置、原始输入不丢且展示正确；未实现多阶段间歇编排引擎，也未对 HIIT 做基于 work/rest/rounds 的热量估算（避免无可靠依据造数）。
2. **有氧热量依赖 slug→MET 命中**：种子动作中 `running/cycling/swimming` 等可算；没有参数库 MET 的动作明确标记“暂不可计算”，保留时长/距离/强度。
3. **远程同步受限**：本机 `git fetch` 因 schannel 吊销检查失败；已通过缓存远端引用 + GitHub API 核验基线与默认分支关系，未覆盖本地分支。
4. **真机验证缺失**：杀进程恢复草稿、Glance 刷新、不同 Launcher/尺寸未做真机验证；本次不宣称通过。
5. **UI 状态保存**：训练录入使用现有 SharedPreferences 草稿机制；旋转/进程恢复沿用项目现有实现，未新增 Compose rememberSaveable 链路。
