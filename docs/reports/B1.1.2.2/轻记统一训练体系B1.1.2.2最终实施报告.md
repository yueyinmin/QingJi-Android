## 一、修复说明

### 1. 副作用失败日志（P1）

**修改前**：`BackupManager.importJson()` 的 `runCatching { SettingsStore.set(...) }` 与 `runCatching { WidgetRefresher.refresh(...) }` 直接吞异常。数据库恢复成功后若 AI 设置写入失败，用户只看到成功，无法定位 AI 配置不一致的原因。

**修改后**：
- 两个副作用分别用 `runCatching` + `onFailure` 记录 `Log.w`，日志文案可区分：
  - `备份恢复已提交：AI 激活服务设置写入失败（<原因>），请手动检查 AI 设置`
  - `备份恢复已提交：桌面组件刷新失败（<原因>），下次进入首页会自动刷新`
- 日志中不改变返回值：数据库已提交时仍返回 `Result.success`，不把外部存储失败重新包装成恢复失败。
- 构造函数新增两个**生产默认值**的注入点 `aiSettingWriter` / `widgetRefresher`，仅测试注入失败；生产仍走真实 DataStore 与 `WidgetRefresher`，业务 UI 无感。

**文件**：`app/src/main/java/com/qingji/app/data/backup/BackupManager.kt`

### 2. importJson 真实入口测试（P1）

**修改前**：只有 `restoreInto()` 级别的测试（手动模拟事务提交后的设置写入），没有验证 `importJson()` 入口的「事务提交 → 应用副作用」顺序。

**修改后**：
- `BackupManager` 新增 `dbOverride: AppDatabase? = null`（与 `TrainingRepository` 同款注入方式），生产不传，测试可注入内存 Room 验证真实入口。
- Robolectric 下用 `ShadowContentResolver.registerInputStream()` 注册 `content://` Uri，走 `ContentResolver.openInputStream()` 真实读取分支。
- 新增 3 个入口测试：
  - 事务提交成功后才应用 AI 设置副作用；
  - 事务中途失败（`restoreHook`）时设置、AI 配置、训练段全部不应用；
  - 两个外部副作用均失败时分别记录可区分日志，且数据库恢复仍返回成功。

**文件**：`BackupManager.kt` + `app/src/test/java/com/qingji/app/training/BackupRollbackB112Test.kt`

### 3. 条件清理失败的提示路径（P1）

**修改前存在两个问题**：
1. `clearIfMatches()` 只返回 Boolean，ViewModel 无法区分「磁盘本来就是空的」和「磁盘还有别的草稿被保留」；`_draft.value == null` 分支不提示，可能出现磁盘草稿仍在但用户完全不知情。
2. 即便走进提示分支，代码也是先 `say("…草稿已保留…")`、紧接着 `say("训练已保存…")`；`_message` 是 StateFlow，后一条会合并掉前一条，**用户实际看不到保留提示**。这不是测试写法问题，是真实 UX 缺陷。

**修改后**：
- `WorkoutDraftStore` 新增 `DraftClearOutcome(cleared, draftRemains)` 与 `clearIfMatchesDetailed()`；读取、身份校验、版本校验、删除仍在同一把进程级 `DRAFT_LOCK` 内完成。原 `clearIfMatches()` 保留为布尔包装，T21–T24 无需改动。
- `TrainingViewModel.save()` 用 outcome 判断：
  - `cleared` → 清内存；
  - `!draftRemains` → 磁盘本来就空，无需提示；
  - 草稿仍在 → 生成 `draftNotice`，**并入最终成功消息**（`"$baseMessage；$draftNotice"`），只 `say()` 一次，保证用户能看到。
- 清理本身抛异常时保守认为草稿仍在（`draftRemains = true`），同样给出提示，不会静默。

**文件**：`WorkoutDraftStore.kt`、`TrainingViewModel.kt`、`TrainingViewModelB112Test.kt`

### 4. 新增测试

- `T25 内存草稿为空但磁盘仍有草稿时保存成功必须提示草稿已保留`（断言最终消息包含保留提示，且 B 草稿未丢、A 已入库）。
- 在 T15 中补强断言：保存期间的新修改提示必须出现在最终成功消息里。
- `importJson事务提交成功后才应用AI设置副作用`
- `importJson事务中途失败时完全不应用AI设置副作用`
- `importJson外部副作用失败分别记录日志且数据库恢复仍成功`

T15–T24 全部保留，未删除、未降级断言。
