## 4. P2 审计结论（优化建议，非缺陷）

### P2-01 批量查询性能
`summariesFor`（`DailyHealthRepository.kt:82-90`）逐日调 `summaryFor`；每次 6 次 SELECT（`:37-41` 五源 + `:59` 缓存），30/90/365 天 = **180/540/2190 次查询**，第 4 项是 `workout_exercise` JOIN `workout_session` + 逐串 JSON 解析（`:40,43-45`）。**缓存命中也照查 5 张源表**，只省 upsert。建议：5 个 DAO 加 `WHERE date BETWEEN` 的 `GROUP BY date` 区间聚合；用现成未用的 `DailyHealthSummaryDao.findRange`（`:17-18`）；签名统一（见 P1-01）；批量 upsert 单事务；与首页/进展页区间查询共用入口。`summariesFor` 当前**无生产调用方**，实际走单日 `summaryFor`（`TrainingDiaryContent.kt:108-110,123`）。

### P2-02 标准食物库初始化与恢复
`FoodCatalogDatabase.ensureFresh`（`:123-137`）**先删库（`:130`）、先写版本号（`:136` apply 异步），再打开/拷贝/校验**——版本号提前写入。资产探测只 `assets.open().close()`（`:146-152`），不校验内容；无 `PRAGMA quick_check`；资产损坏时 `createFromAsset`（`:154-165`）无 try-catch，异常被 `QingJiApp.kt:32-37` 吞。版本号常量 `CATALOG_VERSION`（`:109`）与 Python 脚本手工副本（`fastfood_import.py:43` 等）漂移风险。建议两阶段提交（pending_version → 校验 → installed_version）、prefs 写入移到验证后并改 commit、临时文件+原子 rename、常量单一来源。用户库隔离良好（独立 db + id 分段 `QingJiRepository.kt:72-79` + 标准库 DAO 无写方法），升级不覆盖用户数据。

### P2-03 Repository 依赖与职责边界
所有 Repository 接收 Context 自建数据库（`QingJiRepository.kt:57,59` 等），但因 `AppDatabase.get`/`FoodCatalogDatabase.get` 是 `synchronized` 单例（`:936-955`），**不会重复创建 DB 实例**；但每个 ViewModel 重新 new Repository + `AiClient()`/`OpenFoodFactsClient()`（`QingJiRepository.kt:60-61`），读档案也初始化网络客户端（构造开销待验证）。`QingJiRepository` 1417 行承载本地 DB/标准库/AI/条码网络/KeyStore/DataStore/Widget 刷新/备份（`:54-70,852-1416`）。无 DI 容器。建议轻量 `AppContainer` 持有单例依赖、客户端改 lazy、按域拆 façade、跨仓库事务上移 domain service；**不建议全量重写或引入 Hilt**。稳定不动：DB 单例与迁移链、账本幂等根基、训练事务边界、标准库隔离、AppClock 入口、WidgetRefresher 合并骨架、高覆盖 domain 纯函数。

## 5. 数据流与调用链

1. **每日汇总缓存**：`summaryFor(date)` → 五源 DAO SUM（food/ledger/session/sets/sleep）→ 拼签名 → `findByDate` 比对 → 不符则 `DailyHealthAggregator.aggregate` 重建 + `upsert`（`DailyHealthRepository.kt:35-79`）。
2. **小组件读取降级**：`loadWidgetData` → 跨进程读 DataStore 外观 + 4 个 observe().first() → 成功写 `lastGoodData`，失败回退 `lastGoodData ?: WidgetData()` 并标 stale（`QingJiWidgets.kt:120-163`）。
3. **喝水写入**：`AddWaterAction.onAction` → 600ms 实例防抖 → `QingJiRepository.addWater(200,today)`（写库 + 内部 refresh(OVERVIEW)）→ 成功再 `refreshNow(OVERVIEW)`（`WidgetActions.kt:48-74`、`QingJiRepository.kt:879-899`）。
4. **运动源→账本**：训练路径 `saveSession` 单事务（session+明细+结算+账本+日记）；运动记录路径 `addExercise` 事务内写源 + runCatching 镜像；补算 `ensureLedgerBackfill` 非事务。
5. **时区初始化**：`MainActivity` Compose SideEffect → `AppClock.setZone`；后台/小组件无此步。
6. **区间查询**：`summariesFor` 逐日 `summaryFor`；首页/进展页各自 `observeXxxRange` 原始 Flow 再 ViewModel 内聚合（与 DailyHealthRepository 并行）。
7. **食物库初始化**：`get()` → `ensureFresh`（版本比对→删库→清 WAL→写版本）→ assets 探测 → Room builder（createFromAsset / destructive 兜底）→ INSTANCE（`FoodCatalogDatabase.kt:114-168`）。
